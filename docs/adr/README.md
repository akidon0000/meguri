# ADR: Architecture Decision Records

- 読み手: このアプリを引き継ぐ将来の自分・エージェントセッション
- 位置: `docs/adr/`（索引: このページ、運用: [../handbook/README.md](../handbook/README.md)）
- 目的: Meguri のアーキテクチャに関する意思決定の記録

## いつ書くか

- 実装方針の採用/不採用を決めたとき
- 複数案を比較して構成を選んだとき
- あとから見て「なぜこうなっているか」が自明でない割り切りをしたとき

日々の実装やコードで読み取れることは書かない。iOS アプリ配信の仕組み（asc 採用等）のような
複数リポジトリ共通の判断は書かない → [hq の docs/adr](https://github.com/akidon0000/hq/tree/main/docs/adr) 側にある。

## 書き方

- ファイル名: `NNNN-短いスラッグ.md`（連番 4 桁）
- 冒頭で読み手・目的・状態を宣言する
- 構成: 決定 / 背景 / 比較（表）/ 却下した案 / 再評価のタイミング / 参考
- 決定を覆すときは新しい番号で起票し、旧記録の状態を更新する

| 状態 | 意味 |
|---|---|
| **有効** | 現行構成で採用している |
| **一部置換** | 一部が後続 ADR で置き換わっている |
| **廃止** | 現行構成では採用していない。履歴参照用 |
